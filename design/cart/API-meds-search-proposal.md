# Предложение: API поиска медикаментов

> Статус: **предложение для согласования с бэкендом**, не утверждённая спецификация.
>
> Контекст: UI корзины (`/cart`, вкладка «Медикамент» в модалке «Добавить услугу/медикамент») требует поиска по всей базе МНН и торговых наименований. Существующий `POST /php/API/get-meds.php` (прокси `POST /api/meds`) для этого **не подходит**: это resolve по точному имени строки КР, без частичного совпадения и без поиска по торговому наименованию как входному ключу.
>
> `get-meds.php` и его использование в таблице клинических рекомендаций **не изменять**.

---

## Цель

Дать фронтенду возможность:

1. Искать препараты по подстроке (от 2 символов) по **МНН** и **торговым наименованиям**.
2. Искать по **всей базе**, без привязки к текущей клинической рекомендации.
3. Получать идентификаторы и атрибуты, нужные для корзины и будущей проверки взаимодействий.
4. Не отдавать сотни вариантов дозировок/форм в каждом ответе поиска.

---

## Предлагаемые эндпоинты

Рекомендуется **два** метода (разделение поиска и карточки МНН), чтобы не раздувать выдачу.

### 1. Поиск — `POST /php/API/search-meds.php`

Прокси на фронте (позже): `POST /api/meds/search`.

#### Запрос

```http
POST /php/API/search-meds.php
Content-Type: application/json
Accept: application/json
```

```json
{
  "query": "оме",
  "limit": 24
}
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `query` | string | да | Строка поиска; после `trim` длина ≥ 2 |
| `limit` | number | нет | Максимум результатов; по умолчанию `24`, верхняя граница на усмотрение бэкенда (например 50) |

Нормализация на сервере (рекомендуется):

- `trim`, схлопывание повторяющихся пробелов;
- сравнение без учёта регистра;
- частичное совпадение (prefix и/или substring) по МНН и торговым именам.

#### Ответ `200`

```json
{
  "results": [
    {
      "type": "inn",
      "inn": "ОМЕПРАЗОЛ",
      "label": "Омепразол",
      "hint": "МНН · выберите торговое"
    },
    {
      "type": "trade",
      "inn": "ОМЕПРАЗОЛ",
      "trade": "Омез",
      "label": "Омез",
      "hint": "Омепразол",
      "smnnCode": "21.20.10.112-000001-1-00002-0000000000000",
      "dose": "20 мг",
      "form": "КАПСУЛЫ",
      "atc": "A02BC01"
    }
  ]
}
```

| Поле результата | Тип | Когда | Описание |
|---|---|---|---|
| `type` | `"inn"` \| `"trade"` | всегда | Hit по МНН или по торговому имени |
| `inn` | string | всегда | Стандартизованное МНН |
| `label` | string | всегда | Текст для списка |
| `hint` | string | желательно | Подпись второй строкой |
| `trade` | string | для `trade` | Торговое наименование |
| `smnnCode` | string | желательно для `trade` | Код СМНН варианта |
| `dose` | string | опционально | Доза, если однозначно известна для hit |
| `form` | string | опционально | Форма |
| `atc` | string | опционально | Код АТХ |

**Важно для `type: "inn"`:** в ответе поиска **не** возвращать полный массив торговых имён и variants. Список trades запрашивается вторым эндпоинтом после выбора МНН.

Пустой результат — тоже успех:

```json
{ "results": [] }
```

#### Ошибки

| HTTP | Когда | Тело |
|---|---|---|
| `400` | нет `query`, не строка, или `trim(query).length < 2` | `{ "error": "…" }` |
| `400` | `limit` не число / ≤ 0 | `{ "error": "…" }` |
| `5xx` | сбой upstream / БД | `{ "error": "…" }` |

### 2. Торговые по МНН — `POST /php/API/get-meds-trades.php`

Прокси на фронте (позже): `POST /api/meds/trades`.

Нужен, когда пользователь выбрал hit `type: "inn"` и UI показывает стадию «выберите торговое».

#### Запрос

```json
{
  "inn": "ОМЕПРАЗОЛ",
  "limit": 100
}
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `inn` | string | да | МНН (как в поле `inn` из search) |
| `limit` | number | нет | Ограничение числа торговых; по умолчанию согласовать |

#### Ответ `200`

```json
{
  "inn": "ОМЕПРАЗОЛ",
  "trades": [
    {
      "trade": "Омез",
      "smnnCode": "21.20.10.112-000001-1-00002-0000000000000",
      "dose": "20 мг",
      "form": "КАПСУЛЫ",
      "atc": "A02BC01",
      "unit": "шт. (капсула)"
    }
  ]
}
```

Если у МНН несколько дозировок/форм для одного торгового имени:

- **предпочтительно** вернуть **уникальные торговые** и для каждого — «типовой» / первый вариант `dose`/`form`/`smnnCode`;
- либо вернуть несколько строк с одним `trade` и разными `dose`/`form` — тогда нужно явно согласовать UX (сейчас прототип корзины выбирает одно торговое и подставляет первую пару dose/form).

Если МНН не найден:

```json
{ "inn": "…", "trades": [] }
```

HTTP `200`.

## Поведение, ожидаемое фронтом

| Сценарий | Ожидание |
|---|---|
| Ввод < 2 символов | Запрос **не** отправляется |
| Ввод ≥ 2 символов | Debounce → `search-meds` |
| Hit `inn` | UI → стадия trades → `get-meds-trades` |
| Hit `trade` | UI сразу «выбран препарат» (ready) |
| Пустой `results` | Показать «Ничего не найдено»; доступен ручной ввод |
| Ручной ввод без выбора | Фронт сохраняет `kind: "drug"`, `source: "manual"` без `inn`/`smnnCode` |

Идентификаторы, которые фронт сохранит в пользовательской позиции корзины при выборе из справочника:

- `inn`, `trade`, `smnnCode`, при наличии `dose` / `form`;
- `source: "catalog"`.

Эти поля нужны для последующего подключения проверки взаимодействий (сейчас не активируется).

---

## Что не делать в этом API

- Не смешивать с `get-meds.php` (resolve списка названий КР 1:1).
- Не требовать код МКБ / ключ рекомендации.
- Не возвращать взаимодействия в search-ответе.
- Не опираться на моки `preparaty/data/trades.json`.

---

## Совместимость с текущим фронтом

На этапе до появления API:

- модалка корзины уже умеет стадии `search` / `trades` / `ready` и ручной ввод;
- контракт кандидатов на фронте соответствует полям `DrugSearchHit` / `DrugTradeOption` в `app/(directory)/shared/cart/customCartItem.ts`;
- подключение реального поиска — отдельная задача после согласования и реализации эндпоинтов.

## Открытые вопросы к бэкенду

1. Точный path и нужна ли авторизация / те же cookies, что у остальных EasyMed API.
2. Prefix-only vs substring; ранжирование (сначала prefix, торговые vs МНН).
3. Нужен ли отдельный `smnnCode` на уровне МНН или только у trade-варианта.
4. Как сворачивать несколько dose/form у одного trade в `get-meds-trades`.
5. Лимиты и таймауты (ориентир фронта: ответ < 1–2 с при debounce ~300 мс).
